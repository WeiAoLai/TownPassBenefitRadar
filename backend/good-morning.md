# 長輩圖政策宣傳專案需求文件

## 1. 文件目的

本文件整理長輩圖政策宣傳專案的使用者故事、功能需求、驗收條件、資料模型、MVP 範圍與五人分工。內容只依據目前提供的需求撰寫；尚未確認的規則集中列在「待決事項」。

## 2. 專案目標

讓長輩圖製作者選用台北景點背景與政策標語，製作、儲存及展示長輩圖；其他觀賞者可以表達喜歡並下載附有政策 QR code 的作品。系統以作品累積、徽章與排行榜呈現參與成果。

## 3. 角色

### 3.1 長輩圖製作者

擁有帳號，使用編輯器製作長輩圖，並管理及展示自己儲存的作品。

### 3.2 其他觀賞者

瀏覽作品、點愛心及下載其他人的長輩圖。

> 待決：其他觀賞者是否需要登入，才能點愛心或下載。

## 4. 使用者故事、功能與驗收條件

### US-01：選用景點背景

**使用者故事**
身為長輩圖製作者，我可以在編輯器載入背景圖圖庫中的台北景點圖片，例如龍山寺、台北 101，作為長輩圖背景。

**功能需求**

- 編輯器可顯示可用背景圖。
- 製作者可選擇一張背景圖並載入編輯區。

**驗收條件**

1. 當圖庫內有可用背景時，製作者可以看到背景清單。
2. 點選背景後，編輯區顯示所選圖片。
3. 更換背景時，編輯區改用新選擇的圖片。

### US-02：依政策類別載入標語

**使用者故事**
身為長輩圖製作者，我可以先選政策類別，再選擇想宣傳的政策，將政策標語載入編輯器。

**功能需求**

- 系統顯示政策類別。
- 選定類別後，系統只顯示該類別的政策。
- 製作者選定政策後，可將其標語載入編輯區。

**驗收條件**

1. 製作者可以先選政策類別，再看到該類別下的政策。
2. 點選政策後，編輯區顯示該政策的標語。
3. 儲存作品時，系統保留作品與政策的關聯，供下載時產生 QR code。

### US-03：隨機產生政策長輩圖

**使用者故事**
身為長輩圖製作者，我可以隨機產生政策內容並得到可繼續編輯的長輩圖。

**功能需求**

- 系統可隨機選出一筆可用政策。
- 隨機產生的政策標語會載入編輯器。
- 作品仍可在編輯器內修改。

**驗收條件**

1. 點選隨機產生後，編輯區載入一筆可用政策的標語。
2. 產生結果與該政策的識別碼及來源網址保持關聯。
3. 使用者可以再次隨機產生，取得另一個隨機結果；不保證與前次不同。

> 待決：隨機功能是否同時選背景圖，或只選政策。

### US-04：儲存作品至帳號

**使用者故事**
身為長輩圖製作者，我可以儲存完成的長輩圖，並將作品歸在自己的帳號下。

**功能需求**

- 已登入的製作者可儲存編輯結果。
- 長輩圖圖片檔案存入 Amazon S3。
- 系統記錄作品擁有者、背景、政策、標語、S3 object key 與建立時間。

**驗收條件**

1. 儲存成功後，作品出現在該製作者的作品清單。
2. 其他帳號不得將作品儲存成原作者名下。
3. 重新開啟作品清單時，已儲存作品仍可取得。
4. S3 上傳失敗時，不得將作品標示為儲存成功。

> 待決：是否需要草稿、編輯既有作品、刪除作品與公開／不公開狀態。

### US-05：展示作品與解鎖背景

**使用者故事**
身為長輩圖製作者，我可以在個人頁面展示所有已儲存作品，並在累積儲存 3 張後解鎖新背景。

**功能需求**

- 個人頁面顯示該帳號的作品。
- 系統依帳號的已儲存作品數判斷背景解鎖資格。
- 作品數達 3 張時，解鎖指定的新背景。

**驗收條件**

1. 個人頁面列出該帳號所有符合展示條件的作品。
2. 作品數少於 3 張時，指定背景維持鎖定。
3. 第 3 張作品儲存成功後，指定背景可在背景圖庫選用。
4. 重複讀取頁面時，解鎖狀態保持一致。

> 待決：被刪除的作品是否仍計入解鎖門檻；新背景的圖片內容與授權來源也尚未提供。

### US-06：作品排行榜

**使用者故事**
身為使用者，我可以看到依愛心數與下載數計算的作品排行榜。

**排行榜定義**

- 排名單位：長輩圖作品。
- 每張作品的排行榜分數：`score = max(like_count, download_count)`。
- 依 `score` 由高至低排名。
- 分數相同的作品並列同一名次。畫面顯示順序不改變其名次。
- 愛心數或下載數更新後，排行榜須依最新計數重新計算。

**範例**

| 作品 | 愛心數 | 下載數 | 排行榜分數 |
|---|---:|---:|---:|
| A | 80 | 35 | 80 |
| B | 20 | 95 | 95 |
| C | 60 | 60 | 60 |

依此定義，排名為 B、A、C。

**驗收條件**

1. 每張作品的分數等於愛心數與下載數中的較高值。
2. 排行榜依分數由高至低顯示。
3. 相同分數的作品顯示相同名次。
4. 作品的愛心數或下載數變更後，重新查詢排行榜會反映新分數。

> 待決：排行榜是全期間或限定期間、顯示筆數、更新頻率，以及是否另做製作者排行榜。目前文件只定義作品排行榜。

### US-07：累積作品並取得徽章

**使用者故事**
身為長輩圖製作者，我累積儲存作品後，可以在個人頁面與排行榜看到對應徽章。

**徽章規則草案**

徽章以累積作品數為唯一門檻。十級門檻暫採公比 2，符合「等比例成長」：第 `n` 級門檻為 `2^(n-1)` 張。達到較高門檻後，顯示目前最高等級徽章；是否同時展示歷來取得的徽章列為待決事項。

| 等級 | 徽章名稱 | 累積作品門檻 |
|---:|---|---:|
| 1 | 初心傳聲 | 1 張 |
| 2 | 雙喜分享 | 2 張 |
| 3 | 四方送暖 | 4 張 |
| 4 | 八方傳福 | 8 張 |
| 5 | 鄰里好手 | 16 張 |
| 6 | 社區達人 | 32 張 |
| 7 | 城市傳聲 | 64 張 |
| 8 | 政策推手 | 128 張 |
| 9 | 全民分享家 | 256 張 |
| 10 | 長輩圖典藏家 | 512 張 |

**驗收條件**

1. 系統以製作者的累積作品數判斷徽章等級。
2. 達到門檻時，個人頁面顯示對應徽章。
3. 該製作者的作品出現在排行榜時，排行榜同時顯示其徽章。
4. 未達下一級門檻時，徽章不得提前升級。

> 待決：確認公比是否為 2、徽章名稱與視覺設計、刪除作品是否使徽章降級，以及排行榜上顯示作品作者的最高徽章或其他徽章。

### US-08：對作品點愛心

**使用者故事**
身為其他觀賞者，我可以對喜歡的長輩圖點愛心。

**功能需求**

- 作品顯示愛心操作與目前愛心數。
- 有效的愛心操作會更新作品愛心數，並影響排行榜分數。

**驗收條件**

1. 觀賞者點愛心後，該作品愛心數更新。
2. 排行榜重新計算時，使用更新後的愛心數。

> 待決：同一人能否取消愛心、是否只能點一次，以及未登入觀賞者如何辨識與防止重複計數。

### US-09：下載附政策 QR code 的作品

**使用者故事**
身為其他觀賞者，我可以下載其他人的長輩圖，下載檔案上附有該作品政策的 QR code。

**政策 QR code 定義**

- QR code 內容取自作品所關聯政策的 `source_url`。
- QR code 必須合成在下載檔案中，不只顯示在網頁介面。
- 每次成功提供下載檔案後，該作品的下載數加 1，並影響排行榜分數。
- 若政策缺少可用的來源網址，作品不得進入可下載狀態，避免產生無效 QR code。

**驗收條件**

1. 下載其他人的作品後，取得的圖片檔案含 QR code。
2. 使用一般手機相機或 QR code 掃描工具可辨識該 QR code。
3. 掃描結果等於作品關聯政策的 `source_url`。
4. 成功提供下載檔案後，作品下載數增加 1。
5. 下載數更新後，排行榜重新計算會使用新的下載數。

> 待決：QR code 尺寸、位置、樣式、容錯等級、來源網址允許的網域，以及下載檔案格式與解析度。

## 5. 資料模型

MVP 只使用 4 張資料表：`User`、`Background`、`Policy`、`Artwork`。政策類別直接存於 `Policy`；愛心數與下載數直接存於 `Artwork`；徽章依固定門檻即時計算，不另建資料表。圖片檔案存入 Amazon S3，資料庫只保存 S3 object key。實際型別與索引由後端依採用的資料庫決定。

### 5.1 User

| 欄位 | 說明 |
|---|---|
| `id` | 使用者唯一識別碼 |
| `display_name` | 個人頁面與排行榜顯示名稱 |
| `created_at` | 帳號建立時間 |

> 帳號登入方式、個人資料欄位與權限角色尚未定義。

### 5.2 Background

| 欄位 | 說明 |
|---|---|
| `id` | 背景唯一識別碼 |
| `name` | 背景名稱，例如龍山寺、台北 101 |
| `image_object_key` | 背景圖片在 S3 的 object key |
| `unlock_threshold` | 解鎖所需作品數；預設可用背景可為 0 |
| `is_active` | 是否可在圖庫使用 |

### 5.3 Policy

| 欄位 | 說明 |
|---|---|
| `id` | 政策唯一識別碼 |
| `category` | 政策類別名稱 |
| `title` | 政策名稱 |
| `slogan` | 載入編輯器的政策標語 |
| `source_url` | QR code 指向的政策來源網址 |
| `is_active` | 管理者是否允許選用與隨機產生 |
| `start_date` | 申辦期起日或明確的新版本適用起日；無法可靠界定可為 NULL |
| `end_date` | 申辦截止日期；持續實施或無明確截止日為 NULL |

`is_active` 是管理者上架開關，不表示政策仍在受理或使用者符合資格。本系統的可選政策查詢另行判斷臺北當地日期：`start_date = NULL` 視為無起日限制，`end_date = NULL` 視為持續辦理、無截止日限制；兩者皆有值時 `end_date` 不得早於 `start_date`。政策下架或到期不影響既有作品的瀏覽與下載。

### 5.4 Artwork

| 欄位 | 說明 |
|---|---|
| `id` | 作品唯一識別碼 |
| `owner_id` | 製作者帳號 |
| `background_id` | 使用的背景 |
| `policy_id` | 關聯政策 |
| `slogan_text` | 儲存當下使用的標語內容 |
| `image_object_key` | 儲存後的作品圖片在 S3 的 object key |
| `like_count` | 愛心累積數，初始值為 0 |
| `download_count` | 成功下載累積數，初始值為 0 |
| `created_at` | 建立時間 |

### 5.5 固定設定與衍生值

十級徽章的名稱、門檻與圖示 object key 存於程式設定，不建立 `Badge` 資料表。徽章圖示與背景圖、長輩圖成品一併存入 Amazon S3。

| 衍生值 | 計算方式 |
|---|---|
| `leaderboard_score` | `max(like_count, download_count)` |
| `artwork_count` | 指定製作者納入計算的作品數 |
| `badge_level` | `artwork_count` 已達門檻中的最高等級 |
| `background_unlocked` | `artwork_count >= unlock_threshold` |

> 若確認「每位觀賞者只能對同一作品點一次愛心」，才新增一張 `ArtworkInteraction` 紀錄表，用來辨識重複操作。MVP 在規則確認前不建立此表。

### 5.6 Amazon S3 儲存規則

- S3 存放背景圖、長輩圖成品與徽章圖示。
- 資料庫不保存圖片二進位內容，只保存 object key。
- 後端依 object key 取得圖片，並控制上傳與下載權限。
- S3 bucket 名稱、AWS Region、object key 命名方式與檔案存取方式列為待決事項。

## 6. MVP 範圍

MVP 包含下列項目：

1. 製作者帳號識別，以及作品歸屬帳號。
2. 台北景點背景圖庫與背景選用。
3. 政策類別、政策清單及標語載入。
4. 隨機選擇政策並載入可編輯作品。
5. 儲存作品與個人作品展示頁。
6. 累積 3 張作品後解鎖指定背景。
7. 作品愛心與下載計數。
8. 依 `max(愛心數, 下載數)` 計算的作品排行榜。
9. 十級徽章門檻，以及在個人頁面與排行榜顯示徽章。
10. 下載時將政策來源 QR code 合成至作品。
11. 背景圖、長輩圖成品與徽章圖示存入 Amazon S3。

下列內容尚未有需求依據，不納入目前 MVP：社群留言、分享至外部社群、通知、內容檢舉、後台分析報表、作者排行榜，以及多種排行榜週期。若需加入，須另行確認需求與驗收條件。

## 7. 五人分工

### 7.1 前端 1 人

- 實作背景圖庫、政策分類與選擇介面。
- 實作長輩圖編輯器、隨機政策操作與儲存流程。
- 實作個人作品頁、背景鎖定狀態、愛心、下載、排行榜與徽章顯示。
- 串接後端 API，處理載入、成功與失敗狀態。

### 7.2 後端 1 人

- 建立 `User`、`Background`、`Policy`、`Artwork` 四張資料表。
- 提供政策分類、隨機政策、作品儲存、個人作品、愛心、下載與排行榜 API。
- 實作排行榜分數、背景解鎖與徽章等級計算。
- 產生 QR code，並將 QR code 合成到下載作品。
- 串接 Amazon S3，處理圖片上傳、讀取與下載。
- 確保作品歸屬與計數規則一致。

### 7.3 DevOps 1 人

- 建立開發、測試與正式環境的部署流程。
- 建立 Amazon S3 bucket，設定應用程式存取權限。
- 設定應用程式與資料庫的執行環境。
- 管理環境設定、部署紀錄、備份與基本監控。
- 協助團隊建立自動測試與部署檢查。

> 圖片儲存服務已指定為 Amazon S3。運算服務、資料庫服務、網域與流量規模尚未指定，DevOps 需在技術選型確認後補部署規格。

### 7.4 內容人員 A：政策內容

- 整理政策類別、政策名稱與標語。
- 為每筆政策提供可驗證的來源網址，供 QR code 使用。
- 檢查標語與來源網址的對應關係。
- 標記可上線與暫停使用的政策內容。

### 7.5 內容人員 B：視覺素材與徽章

- 整理台北景點背景清單與圖片素材。
- 確認背景圖的使用授權與標示方式。
- 依十級徽章表製作徽章名稱、圖示與交付規格。
- 提供儲存 3 張後解鎖的背景素材。

### 7.6 共同協作

- 前端與後端共同確認 API 欄位、錯誤格式與圖片輸出規格。
- 後端與政策內容人員共同檢查每筆 `source_url` 是否可用。
- 前端、後端與視覺素材人員共同驗收 QR code 在下載圖片上的可掃描性。
- 全員依本文件的驗收條件確認 MVP。

## 8. 待決事項

以下事項會影響實作或驗收，開始對應工作前須確認：

1. 其他觀賞者是否需要登入；愛心能否取消，以及如何限制重複愛心。
2. 隨機產生是否同時隨機選擇背景圖。
3. 作品是否有草稿、編輯、刪除及公開狀態。
4. 刪除作品後，背景解鎖與徽章是否降級。
5. 解鎖背景的圖片內容、數量與授權來源。
6. 徽章門檻是否採公比 2；徽章名稱與圖示需不需要調整。
7. 個人頁面與排行榜要顯示最高等級徽章，或顯示所有已取得徽章。
8. 排行榜期間、顯示筆數、更新頻率，以及是否需要作者排行榜。
9. QR code 尺寸、位置、樣式、容錯等級與允許的政策網址網域。
10. 下載圖片的檔案格式與解析度。
11. 帳號登入方式，以及需要保存的個人資料欄位。
12. 背景、政策標語、徽章與作品的內容授權及標示規則。
13. S3 bucket 名稱、AWS Region、object key 命名方式、公開或私有存取方式，以及檔案保留規則。
